# Positioning and limits

Mirage must retain runtime-evidence-guided exploration of tensor memory representations coupled with training-state transitions, conditional metamorphic relations, and semantic checkpoint alignment. The new mechanisms repair its proposal-to-evidence pipeline; they are not themselves a claim to have invented constraint-based fuzzing or LLM feedback.

The 2026 GPU-Fuzz preprint overlaps memory-layout exploration, so “first to test memory layout” is unsupported. A narrower candidate contribution is systematic exploration and measurement of API × memory representation × training-state transition × applicable MR, with independently checked path/state evidence. This review does not establish firstness or exhaust all literature. Experiments must demonstrate useful state diversity and applicable comparisons rather than only easy arithmetic success.

This iteration deliberately does not add per-API templates, fixed issue inputs, looser tolerances, runtime-success certificates, or blanket classification of exceptions as framework defects. Structured unresolved proposals remain planning uncertainty; they are not proofs of unreachability. Pure-build certificate extensions must accompany stronger binding and effect checks.
